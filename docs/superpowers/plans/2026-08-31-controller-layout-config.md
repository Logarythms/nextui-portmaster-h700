# Configurable Controller Layout (Nintendo/Xbox) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user pick Nintendo or Xbox face-button layout (globally in the PortMaster GUI, per-game via config), with one resolved value driving every port class and the GUI's own confirm/back — factory default Nintendo.

**Architecture:** A single key `gt-controller-layout` in PortMaster's own `config.json` is the source of truth. `launch.sh` resolves the effective layout per launch (via a standalone POSIX helper the bundled `jq` reads), applies it to the SDL `gamecontrollerdb.txt` and exports `GT_CONTROLLER_LAYOUT`; the input shim reads that env and swaps a↔b / x↔y for keyboard/gptk/evdev synth ports. The GUI is patched (via the existing `patch_pylibs` rail) so `PlatformTrimUI.loaded()` drives `WANT_XBOX_FIX`/`WANT_SWAP_BUTTONS` from the same key, plus an `OptionScene` toggle that writes it.

**Tech Stack:** POSIX sh (launch.sh + resolver), awk (build-pak.sh injection), C (gt-input-remap shim), Python 3 (harbourmaster/pugwash pylibs patches), shell fixture tests (`tests/run.sh`).

**Spec:** `docs/superpowers/specs/2026-08-31-controller-layout-config-design.md`

## Global Constraints

- **Config key:** `gt-controller-layout`, value `"nintendo"` | `"xbox"`. Per-game override object `gt-port-layout` mapping `ROM_NAME` (launcher filename, e.g. `"Sonic 1.sh"`) → `"nintendo"` | `"xbox"`. Both live in `config.json`.
- **Config path (device):** `$EMU_DIR/config/config.json` (`$EMU_DIR = $SDCARD_PATH/Emus/$PLATFORM/PORTS.pak/PortMaster`). Read with the bundled `jq` (on PATH from launch.sh).
- **Resolution precedence (high→low):** per-game `gt-port-layout[ROM_NAME]` → global `gt-controller-layout` → legacy `nintendo*` marker file in `PORTS-portmaster` → factory default `nintendo`. Every read fails safe to the next tier (missing file/key, malformed JSON, unrecognized value).
- **Never hand-edit `dist/.../launch.sh` or the pylibs `.py` files.** launch.sh gt-h700 blocks are injected by `build/build-pak.sh` (`edit_portmaster_launch`); pylibs edits run at launch via `patch_pylibs` invoking helper scripts in `PortMaster/../src/`. `dist/` is regenerated by `make pak`.
- **Polarity (which layout is the "swapped" one) is confirmed at the device gate** (Task 7). The shim and `platform.py` both implement *nintendo = current/unswapped* as the starting point (zero regression for the new default); if the gate shows shim ports or the GUI come out reversed, it is a one-line boolean flip in each. This is a gate acceptance criterion, not a code unknown.
- **Shim binaries (`gt-input-remap.so`, `gt-input-remap.armhf.so`) are rebuilt with `make shim`** (docker; needs network for `apt`, so run with `dangerouslyDisableSandbox`). `make shim` ends with a `file` check — both must be ARM aarch64 / EABI5 armhf respectively.
- **`make test` must stay green** and is `sh tests/run.sh` (host-only; C-compiling tests SKIP when no `cc`, jq tests SKIP when no `jq` — mirror `tests/test-23-sleepmon-host.sh`).
- **Fix number: F48.** Follow `docs/pak-release-notes-style` for any notes.
- **Process:** branch `controller-layout-config` (already created off `8882c79`); one squashed commit at the end (docs fold in); joins the existing unpushed bundle — **no push/tag/release until Camille says**; device gate (Task 7) before any of that.

- [ ] **Step 1: Write the resolver** — `assets/gt-controller-layout.sh`:

```sh
#!/bin/sh
# gt-controller-layout (F48): resolve the effective controller layout for a
# launch. Echoes "nintendo" or "xbox". Single source of truth = PortMaster's
# config.json. Precedence high->low:
#   1. per-game   cfg.gt-port-layout["<ROM_NAME>"]   ($1)
#   2. global     cfg.gt-controller-layout
#   3. legacy     a "nintendo*" file in PORTS-portmaster   -> nintendo
#   4. factory    nintendo
# Every read fails safe to the next tier (missing file/key, malformed JSON,
# unrecognized value). Reads EMU_DIR + USERDATA_PATH from the launch env.
#   $1 = ROM_NAME (launcher filename, e.g. "Sonic 1.sh"); optional (GUI: omit).
rom_name=${1:-}
cfg="${EMU_DIR:-}/config/config.json"

valid() { [ "$1" = "nintendo" ] || [ "$1" = "xbox" ]; }

if [ -f "$cfg" ] && command -v jq >/dev/null 2>&1; then
    if [ -n "$rom_name" ]; then
        v=$(jq -r --arg n "$rom_name" '.["gt-port-layout"][$n] // empty' "$cfg" 2>/dev/null)
        if valid "$v"; then echo "$v"; exit 0; fi
    fi
    v=$(jq -r '.["gt-controller-layout"] // empty' "$cfg" 2>/dev/null)
    if valid "$v"; then echo "$v"; exit 0; fi
fi

if [ -n "${USERDATA_PATH:-}" ] && \
   [ -n "$(find "$USERDATA_PATH/PORTS-portmaster" -maxdepth 1 -iname 'nintendo*' -type f 2>/dev/null)" ]; then
    echo "nintendo"; exit 0
fi

echo "nintendo"
```
